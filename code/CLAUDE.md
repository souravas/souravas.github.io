# /code

- **Content**: [PATTERNS.md](PATTERNS.md) (algorithm templates), [CHEATSHEET.md](CHEATSHEET.md) (syntax and idioms, no algorithms) and [README.md](README.md) (the Overview: the solution trees, how to run them, interview-day tips) are the only copies. The solutions stay in the `souravas/code` repo, whose README and the vault's `70 - Learn/Code/Python Code.md` just link here.
- **Writing conventions**: between them, Patterns and Cheatsheet cover every technique in the solutions. Put new material on the right side of the line between them, and give a problem its own subsection only if it shows something its template doesn't. They're read on a phone under time pressure: keep code blocks self-contained and prose short, and explain a non-obvious step in a comment on that step. The longest code line (93 characters) fits unwrapped from 900px; below that, code wraps under its indent. Adding or renaming a `##` heading means updating the document's Table of Contents and any links to it.
- **Links**: keep plain file links with GitHub's anchors (`PATTERNS.md#fast--slow-pointers`). The page uses the same anchors as ids, so a link works both here and on GitHub. In a code comment, `PATTERNS.md → Sorting` becomes a link.
- **Rendering**: the `code-docs` plugin in vite.config.js runs [render.js](render.js) (build-time only) into `index.html` at its `<!--docs-->` and `<!--sections-->` markers. It renders only the three documents listed in its `DOCS`, highlights the Python at build time, reloads dev when a document is saved, and warns about dead `#` links; in a build a dead link is an error. Supported Markdown: headings, pipe tables, lists, fenced and inline code, bold, italics, links.
- **Code blocks**: each line is a `.l` span (indent `.w`, code `.x`, end comment `.t`; `.e` and `.a` for a line with an end comment). Each line keeps its newline in the text, so a block's `textContent` is exactly its source; Copy, search and hand selection depend on that.
- **Modules**: `main.js` (section on screen, Sections sheet, Cover, Copy) and [search.js](search.js), which searches the page's own DOM, so nothing is downloaded. main.js also registers the shared [/sw.js](../public/sw.js) with scope `/code`, so the page opens without a network.
- **Styles**: the masthead, bar, text, tables, sheet and footer are [shared/reader.css](../shared/reader.css), which /kannada uses too; `style.css` holds what is this page's own (the code blocks, the rail, search). `--side` and `--side-end` are the page's side padding on a phone.
- **Tests**: `render.test.js`, run by `npm test`. It holds the rule above that a block's text is its source.
- Each `##` section is `content-visibility: auto`, with render.js's estimate of its height in `data-h`. Measuring anything inside a skipped section forces it to lay out, so main.js finds the section on screen by measuring the sections, never what is inside them.
- It is a reference, not a course, so it has no quizzes or review.
