# /downloads

- Typing `souravas.com/downloads` opens the user's Downloads sites as [/cloud](../cloud/CLAUDE.md) opens the cloud drives: all but the first in new tabs, in order, then this tab moves to the first with `location.replace`. /start links it as the last bookmark in Fun (alias `dl`).
- **The sites are never in the repository.** The user wants them kept on their own machine, so the page holds an empty `ol.sites`, and [main.js](main.js) fills it from the browser's `localStorage` (key `downloads:sites`, a JSON array of addresses) before it loads [../shared/opener.js](../shared/opener.js) with a dynamic `import()`, since the opener reads `.sites` as it loads. Never write the addresses into `index.html`, `start/bookmarks.html` or these notes. The old Downloads bookmark's addresses (removed from /start in November 2026) are still in the git history.
- **The editor** shows when the browser holds no list, and at `#edit`: a box of addresses, one per line, which *Save* stores, and an import that fills the box from a browser's bookmarks export (the Netscape HTML every browser writes), taking the links in its folder named `Downloads`, subfolders included. The file is parsed with `DOMParser` in the page and sent nowhere. Only `http:` and `https:` addresses are kept, and none ever comes from the page's URL, so no souravas.com link can add a site.
- The list is per browser and per device, and clearing souravas.com's site data deletes it; the editor says so.
- Pop-ups, prerendering and the layout are /cloud's (see its notes): [style.css](style.css) imports [../shared/opener.css](../shared/opener.css) and adds only the editor's styles.
- No service worker; it loads the analytics beacon like every built page.
