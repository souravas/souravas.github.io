# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project Overview

Sourav's portfolio website. Vanilla HTML / CSS / JS built with Vite — no framework. GitHub Actions builds the Vite output and deploys directly to GitHub Pages via `actions/deploy-pages`.

## Development Commands

```bash
npm install
npm run dev       # dev server on http://localhost:5173
npm run build     # production build → dist/
npm run preview   # preview the production build
```

## Deployment

Pushes to `main` are built and published by [.github/workflows/deploy.yml](.github/workflows/deploy.yml) — modern `actions/deploy-pages` path, no `gh-pages` package, no manual `dist/` copy step. Pull requests run the build only, without deploying. The workflow also exposes a *Run workflow* button (`workflow_dispatch`). [.github/workflows/rebuild.yml](.github/workflows/rebuild.yml) starts that workflow on the 1st of each month, so the build-time values below roll over without a push; the schedule lives in its own file because GitHub switches off a scheduled workflow after 60 days without repository activity, and that must never stop deploys on push.

## Architecture

- **Four page versions**: [v1/](v1/) is the default design, "Editorial". [v2/](v2/) is the editorial "Systems Ledger" design, [v3/](v3/) the observability-console "Control Room" design, and [v4/](v4/) the "Plain" design (one Newsreader serif column with hairline rules, no effects, nothing hidden behind JS, and a print stylesheet that turns it into a CV). Each is self-contained: `index.html` + `main.js` + `style.css` (v2, v3 and v4 also bundle their own `fonts/`). v4 has its own social card, `public/assets/og-cover-v4.jpg` + `.webp`, set in its type; v1–v3 share `og-cover`. Every version names `/` as its canonical, so search engines index one copy of the résumé, while `og:url` stays per version so each shares with its own card. The footer's design switcher links the default as `/` and the others as `/vN/`. No framework, no router — each version is one page with anchor sections.
- **Start page**: a personal bookmarks dashboard at `/start`, built from [start/](start/): pure black, v1's shared `public/fonts/`, an inline prompt that filters the links in place (by alias, then link name, ranking word starts first, then the name's initials (`pp` finds Proton Pass), then the inside of a word, then site name; Enter opens the best match, Ctrl/⌘+Enter in a new tab; an alias plus a query, like `lc two sum`, opens that link's search), and clickable group headings that open every link in the group (the heading button is injected by its `main.js`; browsers block every tab after the first as a pop-up until the site is allowed pop-ups). It is the browser homepage, so links open in the same tab, and [public/start-sw.js](public/start-sw.js), a service worker registered by its `main.js` in production with scope `/start`, serves `/start` and `/start/` from cache (instant and offline) and refreshes the cache in the background, so a deploy shows up on the second open (the unhashed shared `/fonts/` are revalidated by ETag on each refresh). Each group is a block, its heading above its links in two columns, so a group fills whole rows (only Security's odd count leaves a cell empty). The page is top-aligned on phones; on wider screens it is centred in the window, so a tall monitor isn't left with an empty lower half, and starts at the top once it outgrows the window. On wider screens the blocks run in two, three (from 1120px) or four (from 1480px) newspaper-style columns 64px apart, never splitting a group, which the browser balances so the columns end close together; there the rows (`--row`) and the gaps around the groups (`--gap`) grow with the window's height, from 32px and 24px in a 640px-tall window to 40px (rows from 720px, gaps from 800px), so the page fills a laptop's browser window, and three columns fit without scrolling down to 640px. On phones the blocks stack in one column to keep the page short, and a group heading there takes about as much height as a row of links. Bookmarks are plain `<li>` links and icons are `<symbol>`s in the page's inline SVG sprite. A link's optional `data-alias` holds its short codes (named in the prompt's hint on hover or keyboard focus), `data-search` a search URL with `%s` for the query, and `data-also` more URLs, space-separated, that open in new tabs along with the href, in order (a click or middle-click, Enter in the prompt and the group heading all open the whole list); Coursera uses it to open both of its courses (Learning How to Learn, then The Science of Well-Being), and Downloads to open the download sites at once, then Trakt's calendar last (Trakt keeps its own link in Media too). Obsidian is an app link that opens the desktop app (`obsidian://open?vault=hope`) and does nothing where the app isn't installed; the prompt matches it on its scheme as the site name. Code opens the `code` repo on GitHub (`https://github.com/souravas/code`), and its `gh` search searches that repo's code. Tasks, Habits, Calendar and Countdown open TickTick's web app at that view (`https://ticktick.com/webapp/#q/all/tasks`, `#q/all/habit`, `#c/all/calendar/w`, `#countdown`): its desktop app opens only a few smart lists from a `ticktick://` link and none of the other three. Claude opens claude.ai at its usage settings (`https://claude.ai/new#settings/usage`), which the desktop app takes no link to; its search, `https://claude.ai/new?q=%s`, opens a new chat with the query typed in. The groups hold the curated learning bookmarks (Daily, Code, Design, Learn, Fit, Skill, Social, Finance, Media, Cloud, Security). Daily comes first and holds the everyday links, TickTick's Tasks, Habits, Calendar and Countdown, then Fitness, Claude, Obsidian and Cashflow, in that order; Fit opens with Exercises, which opens souravas.com/exercises; Skill opens with Kannada, which opens souravas.com/kannada, then holds Typing and the book-summary apps Headway and 12min; Social holds Gmail and the social sites; Finance holds Zerodha's Kite and Coin, then the IPO sites IPO Watch and Chittorgarh; Media holds YouTube, YouTube Music, Comix, YouTube's Playlists, Trakt's calendar, then Downloads; Cloud holds Google Photos, Google Drive, Drime and Koofr; Security comes last and holds Proton Pass, AdGuard DNS and SimpleLogin; the other groups say what their links are. It is `noindex` and left out of the sitemap.
- **Kannada page**: [kannada/](kannada/) is served at `/kannada`, the target of /start's Kannada link. It shows the Obsidian note *Kannada Gottilla* (`70 - Learn/Language/Kannada Gottilla.md` in the `hope` vault: 89 lessons of spoken Bangalore Kannada, plus the notation, routine, lesson index and ending sheet) as one long page, on /start's pure black with its tokens and shared `public/fonts/`. [kannada/note.md](kannada/note.md) is a verbatim copy of the note and the page's only content, so to update the page, copy the note over it. The `kannada-note` plugin in [vite.config.js](vite.config.js) renders it with [kannada/render.js](kannada/render.js) (build-time only; the browser never loads it) into `index.html` at its `<!--note-->` and `<!--lessons-->` markers. That happens in dev too, where saving the note reloads the page, and the plugin warns about any `#` link that lands on no id, such as a renamed heading. The renderer reads only the Markdown the note uses: headings, pipe tables, lists, callouts (folded ones become `<details>`), code, bold, italics, links, and wiki-links (`[[#Heading|alias]]` within the note; a link to another note opens it through `obsidian://open?vault=hope`). It also links every "Lesson N" in the text. Each `#` heading opens a `section.part`, each `## Lesson N — Title` a `section.lesson` with id `lesson-N`, and a heading inside a lesson gets a `lesson-N-…` id (Lessons 29 and 33 both have a "Speak"). Kannada is set in JetBrains Mono because Inter Tight draws capital `I` and `l` alike, and the notation's capitals mark sounds (`iddIra`). That covers code spans, every table column not headed in English (`ENGLISH_COLUMNS` in render.js; a cell with backticks stays English), and the exercise lines, answers and paragraphs whose words weigh as Kannada (a capital inside a word, or a word from the Kannada columns or backticks). A sticky bar links the top-level headings, names the lesson on screen, and opens a popover of all 89 lesson numbers: a bottom sheet on phones, a centred panel on wider screens. Its Cover button carries out the note's routine (cover the Kannada and say each line from the English): it hides the Kannada table cells the renderer marks `.c`, and a tap shows one. Wider screens put each lesson's number in a 120px gutter, and a print stylesheet prints it black on white. Each lesson is `content-visibility: auto`, so a phone lays out only the lessons near the screen (first paint, Cover and a rotation stay quick). Reading where anything inside a skipped lesson sits lays it out again, so main.js finds the lesson on screen by the lesson sections themselves, never their headings. Skipping clips a lesson to its box, so the box reaches over the page's side padding, where the tables bleed, and on phones a lesson's last margin is dropped to keep the gap it used to fold into. It is `noindex` and left out of the sitemap.
- **Exercises page**: [exercises/](exercises/) is served at `/exercises`, the target of /start's Exercises link (in Fit). It lists five exercises, Squats, Glute Bridges, Plank, Pushups and Band Rows, numbered in the order the user gave them, each a link to its YouTube video that opens in the same tab, as /start's links do, so Back returns to the list. Just `index.html` and `style.css`, no script, on /start's pure black with its tokens and the shared `public/fonts/`; a "‹ Start" link leads back, in the 120px gutter on wider screens. It is `noindex` and left out of the sitemap.
- **Multi-page Vite build** with `v1/index.html`, `v2/index.html`, `v3/index.html`, `v4/index.html`, `start/index.html`, `kannada/index.html`, and `exercises/index.html` as inputs, output to `dist/`; that directory is what gets uploaded as the Pages artifact. The `root-default` plugin in [vite.config.js](vite.config.js) copies each default page into place (`DEFAULT_PAGES`): built `v1/index.html` → `dist/index.html`, so `/` serves v1. Assets are hashed; each page's CSS bundle is inlined into its HTML by the `inline-css` plugin, so production has no render-blocking stylesheet request.
- **`public/`** is copied verbatim into the build: `CNAME`, favicons, manifest, `robots.txt`, the redirect stubs (`cv.html`, `resume.html`), the `/start` service worker (`start-sw.js`), v1's `fonts/`, and `assets/` (images + `resume.pdf`). The favicons (`favicon.svg` with its PNG/ICO renders, plus the full-bleed `icon-maskable.svg` that `apple-touch-icon.png` is rendered from) are shared by every page and linked with a `?v=` query: bump it on every page, `404.html` included, when the icons change, or browsers keep showing the cached ones.
- **CSP**: inline theme bootstraps, JSON-LD scripts, and the inlined stylesheets are tightened at build time by the `csp-inline-hashes` Vite plugin in [vite.config.js](vite.config.js), which computes SHA-256 hashes for each inline `<script>`/`<style>` and replaces `'unsafe-inline'` in the CSP meta tag. Dev mode keeps `'unsafe-inline'` so HMR works.
- **Build-time values**, all in [vite.config.js](vite.config.js): the `build-stamps` plugin fills tokens in every page, in dev as well as the build — `__BUILD_DATE__`, `__BUILD_YEAR__`, and the years since the career began in June 2019 (`CAREER_START`) as `__YEARS__` (7), `__YEARS_00__` (07), `__YEARS_WORD__` (seven), `__YEARS_WORD_CAP__` (Seven) and `__YEARS_ORDINAL_CAP__` (Seventh). Write those tokens, never the number, wherever copy states the years. The one exception is `og-cover.jpg`/`.webp` (v1–v3's card), which has "7 years" drawn into it. The sitemap lists only `/`, with the build date as `lastmod`, and `/.well-known/security.txt` is emitted with an `Expires` 364 days out (RFC 9116 wants less than a year); its contact address is `SECURITY_CONTACT`.
- **404 page**: [public/404.html](public/404.html) is a self-contained static page that GitHub Pages serves for unknown routes.

## Site Structure

```
/                 → portfolio, v1 design (default; build-time copy of /v1/)
/v1               → portfolio, v1 design
/v2               → portfolio, v2 design
/v3               → portfolio, v3 design
/v4               → portfolio, v4 design
/start            → start page, the browser homepage (noindex)
/kannada          → Kannada Gottilla, the Kannada lessons note as a page (noindex)
/exercises        → exercise videos, behind /start's Exercises link (noindex)
/cv, /resume      → meta-refresh redirect to /assets/resume.pdf
                    (static stubs in public/; dev server rewrites
                     /cv → /cv.html via html-routes plugin in vite.config.js)
/sitemap.xml      → generated at build time
/.well-known/security.txt → generated at build time
```

The dev server mirrors production routing: the `html-routes` plugin rewrites `/` and `/v1` → `/v1/index.html`, `/v2` → `/v2/index.html`, `/v3` → `/v3/index.html`, `/v4` → `/v4/index.html`, `/start` → `/start/index.html`, `/kannada` → `/kannada/index.html`, and `/exercises` → `/exercises/index.html`.
