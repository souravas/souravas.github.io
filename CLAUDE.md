# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project Overview

Sourav's portfolio website. Vanilla HTML / CSS / JS built with Vite — no framework. GitHub Actions builds the Vite output and deploys directly to GitHub Pages via `actions/deploy-pages`.

## Development Commands

```bash
npm install
npm run dev       # dev server on http://localhost:5173
npm run build     # production build → dist/
npm run preview   # preview the production build
```

## Deployment

Pushes to `main` are built and published by [.github/workflows/deploy.yml](.github/workflows/deploy.yml) — modern `actions/deploy-pages` path, no `gh-pages` package, no manual `dist/` copy step. Pull requests run the build only, without deploying. The workflow also exposes a *Run workflow* button (`workflow_dispatch`). [.github/workflows/rebuild.yml](.github/workflows/rebuild.yml) starts that workflow on the 1st of each month, so the build-time values below roll over without a push; the schedule lives in its own file because GitHub switches off a scheduled workflow after 60 days without repository activity, and that must never stop deploys on push.

## Architecture

- **Four page versions**: [v1/](v1/) is the default design, "Editorial". [v2/](v2/) is the editorial "Systems Ledger" design, [v3/](v3/) the observability-console "Control Room" design, and [v4/](v4/) the "Plain" design (one Newsreader serif column with hairline rules, no effects, nothing hidden behind JS, and a print stylesheet that turns it into a CV). Each is self-contained: `index.html` + `main.js` + `style.css` (v2, v3 and v4 also bundle their own `fonts/`). v4 has its own social card, `public/assets/og-cover-v4.jpg` + `.webp`, set in its type; v1–v3 share `og-cover`. Every version names `/` as its canonical, so search engines index one copy of the résumé, while `og:url` stays per version so each shares with its own card. The footer's design switcher links the default as `/` and the others as `/vN/`. No framework, no router — each version is one page with anchor sections.
- **Start page**: a personal bookmarks dashboard at `/start`, built from [start/](start/): pure black, v1's shared `public/fonts/`, an inline prompt that filters the links in place as you type or paste anywhere on the page (by alias, then link name, ranking word starts first, then the name's initials (`dp` finds Design Patterns), then the inside of a word, then the link's addresses: its site's name, anywhere in it (`headway` finds Books), or the start of any other word in them, a subdomain, a `data-also` host or, on this site, the path (`drive` finds Cloud, `kannada` Language); a group's open-all is offered when its name starts with the query; Enter opens the best match, Ctrl/⌘+Enter in a new tab; an alias plus a query, like `lc two sum`, opens that link's search), and clickable group headings that open every link in the group (the heading button is injected by its `main.js`; browsers block every tab after the first as a pop-up until the site is allowed pop-ups). It is the browser homepage, so links open in the same tab, and [public/start-sw.js](public/start-sw.js), a service worker registered by its `main.js` in production with scope `/start`, serves `/start` and `/start/` from cache (instant and offline) and refreshes the cache in the background, so a deploy shows up on the second open (the unhashed shared `/fonts/` are revalidated by ETag on each refresh). Below 1120px each group is a block, its heading above its links in two columns, so a group fills whole rows (an odd count would leave a cell empty, so every group holds an even count). The page is top-aligned on phones; on wider screens it is centred in the window, so a tall monitor isn't left with an empty lower half, and starts at the top once it outgrows the window. From 760px the blocks run in two newspaper-style columns 64px apart, never splitting a group, which the browser balances so the columns end close together. From 1120px each group is one row instead: its heading in a 96px gutter (`--gutter`) on the left, its links in six equal columns that line up from group to group, so they read left to right in their order, and the prompt starts past the gutter, its mark over the icons. No group holds more than six (one would wrap to a second row; groups are set further apart than the rows inside one, so the two stay apart). From 760px the rows (`--row`) and the gaps around the groups (`--gap`) grow with the window's height, from 32px and 24px in a 640px-tall window to 40px (rows from 720px, gaps from 800px), and the row layout fits without scrolling down to 640px. On phones the blocks stack in one column to keep the page short, and a group heading there takes about as much height as a row of links. Bookmarks are plain `<li>` links and icons are `<symbol>`s in the page's inline SVG sprite. A link's optional `data-alias` holds its short codes (named in the prompt's hint on hover or keyboard focus), `data-search` a search URL with `%s` for the query, and `data-also` more URLs, space-separated, that open in new tabs along with the href, in order (a click or middle-click, Enter in the prompt and the group heading all open the whole list). Downloads' list ends with Trakt's calendar, which has its own link in Media too, so Media's open-all opens it twice; that is known and left as is. Obsidian is an app link that opens the desktop app (`obsidian://open?vault=hope`) and does nothing where the app isn't installed; the prompt matches it on its scheme as the site name. Code, in Daily (not the Code group), opens the `code` repo in github.dev, VS Code in the browser, and its `gh` search searches that repo's code on GitHub. TickTick opens four views of its web app rather than its desktop app, which opens only a few smart lists from a `ticktick://` link. Claude opens claude.ai at its usage settings (`https://claude.ai/new#settings/usage`), which the desktop app takes no link to; its search, `https://claude.ai/new?q=%s`, opens a new chat with the query typed in. Which links each group holds, and in what order, is [start/index.html](start/index.html)'s to say, not this file's; Daily, first, holds the everyday links. It is `noindex` and left out of the sitemap.
- **Kannada page**: [kannada/](kannada/) is served at `/kannada`, the target of /start's Language link. It shows the Obsidian note *Kannada Gottilla* (`70 - Learn/Language/Kannada Gottilla.md` in the `hope` vault: 89 lessons of spoken Bangalore Kannada, plus the notation, routine, lesson index and ending sheet) as one long page, on /start's pure black with its tokens and shared `public/fonts/`. [kannada/note.md](kannada/note.md) is a copy of the note and the page's only content. It was edited here for the page's lessons (Lesson 1 cut to a ten-minute start; every Beginner lesson, 1 to 32, trimmed to a day's lines with its look-up tables, extra examples and written forms folded under For later, nothing deleted; and each ending on a Say it today, which in Lessons 2 to 7 are street lines brought forward from Lessons 58 and 60), so the repo's copy is the newer one: copy it back into the vault before editing the note there, and after that, to update the page, copy the note over it. The `kannada-note` plugin in [vite.config.js](vite.config.js) renders it with [kannada/render.js](kannada/render.js) (build-time only; the browser never loads it) into `index.html` at its `<!--note-->` and `<!--lessons-->` markers. That happens in dev too, where saving the note reloads the page, and the plugin warns about any `#` link that lands on no id, such as a renamed heading. The renderer reads only the Markdown the note uses: headings, pipe tables, lists, callouts (folded ones become `<details>`), code, bold, italics, links, and wiki-links (`[[#Heading|alias]]` within the note; a link to another note opens it through `obsidian://open?vault=hope`). Two callout kinds are the page's own, and Obsidian draws them as plain notes: `> [!say] Say it today` holds the line to use on a real person that day (a one-row English and Kannada table), lit in the accent, and `> [!later]- For later` folds a lesson's look-up material, so the lesson itself stays a day's work. It also links every "Lesson N" in the text. Each `#` heading opens a `section.part`, each `## Lesson N — Title` a `section.lesson` with id `lesson-N`, and a heading inside a lesson gets a `lesson-N-…` id (two lessons can share a heading's words). Kannada is set in JetBrains Mono because Inter Tight draws capital `I` and `l` alike, and the notation's capitals mark sounds (`iddIra`). That covers code spans, every table column not headed in English (`ENGLISH_COLUMNS` in render.js; a cell with backticks stays English), and the exercise lines, answers and paragraphs whose words weigh as Kannada (a capital inside a word, or a word from the Kannada columns or backticks). A sticky bar links the top-level headings, names the lesson on screen, and opens a popover of all 89 lesson numbers: a bottom sheet on phones, a centred panel on wider screens. Its Cover button carries out the note's routine (cover the Kannada and say each line from the English): it hides the Kannada table cells the renderer marks `.c`, and a tap shows one. Each lesson with cards ends on a Quiz button. render.js builds the cards from the lessons' own tables, so they never hold a line the note does not: a card per row and Kannada column, asked from the row's English (the column headed English, else Meaning or What it means, else Number or Case), with a hint (the column's heading, the lesson's subheading and the row's other English) when a table's cards come from differently headed columns. Left out are tables in `[!later]` folds, exercise tables (an Answers callout follows them; their rows are shuffled on purpose), cells with backticks, columns the English does not translate (`SKIP_COLUMNS`) and lines over 140 characters. A card's id is a hash of its English and Kannada, so a line two lessons share is one card. The `kannada-note` plugin writes the cards to `/kannada/cards.<hash>.json`, named in the page's `<meta name="cards">` (the `<!--cards-->` marker), and [kannada/cards.js](kannada/cards.js) fetches it once the page is idle; each table with cards carries a `data-deck` key (`12.3`), which names its cards in that file, and a table of three or more has a Drill button under it (render.js writes it hidden; main.js shows it) that runs just that table, every card to say out loud, twenty-five at a time, without touching the review. A For later table can be drilled too: its cards sit in the file's `drills`, apart from the lesson's own `decks`, so they stay out of its quiz and the review. The checkpoints (Lessons 33, 69 and 89) have no quiz: each exercise that an Answers callout follows has a Run as cards button above its answers instead, built by render.js's `checkCards` item for item against the answers (its note after " — " as the hint), or, for Lesson 33's shuffled Match the Pairs table, from the pairs its answers name. A prompt that weighs as Kannada (a blank to fill, a fast line to decode) is shown as Kannada. Their results go into the review, and the day's plan calls the step Test. With a Kannada voice on the device (Google's speech engine on Android, Edge's online voices on Windows; [kannada/speech.js](kannada/speech.js) looks for a `kn` voice through `speechSynthesis` and marks the root `can-speak`), a tap on any Kannada in the note says it (in Cover, the tap that shows a cell says it and the one that hides it does not), a quiz says each answer as it is shown and has Hear it on the Kannada it shows, and Lesson 1's pairs become "which one did you hear?". Without one, nothing is tappable and Start here says why. The voice reads script, so [kannada/script.js](kannada/script.js) turns the note's spelling into Kannada script (the capitals' sounds, the y between joined vowels, the anusvara before a stop of its own kind) and leaves English words and names in English letters for the voice to read as English: those are listed in its `ENGLISH` and `NAMES`, every one the note's Kannada lines use, so a new English word or name in the note goes there, or it is read as Kannada. A capital alone does not make a name (`Enu`, `ELu`), and `SAID_AS` puts the names the note says how to say (`kannaDa`, `bengaLooru`) into script. Only the Kannada before a spaced dash is spoken, not the English gloss after it. The same cards go out as an Anki deck at `/kannada/anki.txt` (render.js's `ankiDeck`, emitted by the `kannada-note` plugin and served in dev; Start here and the footer link it): Anki's text import with its `#` settings, each lesson's own cards and the checkpoints', each once, in the lesson it is first learned in and in order, a subdeck per lesson (`Kannada Gottilla::01 Sounds That Change the Meaning`), lessons' lines as Basic and reversed and the checkpoints' as Basic, the back in the note's letters and in script, and the card's id as the GUID, so importing the file again updates the cards rather than doubling them. [kannada/deck.js](kannada/deck.js) runs a quiz in a `<dialog>` (full screen on phones): up to eight of the lesson's cards, its Say it today lines always, Lesson 1's sound pairs as "which one means", then half the lines to recognise (the Kannada, and the English to pick from four; wrong answers come from the lesson and the ones before it) and half to say out loud, show and mark Got it or Not yet. Nothing is typed, on purpose. A miss comes back at the end of the run, up to twice. [kannada/store.js](kannada/store.js) keeps the review in localStorage (`kannada`; this browser only, and the page works without it): Leitner boxes, where a card in box n comes back 1, 3, 7, 14, 30 or 60 days after it was last right and a miss goes back to box 1, due tomorrow. A quiz's answers place its cards (new ones start in box 1, due tomorrow; a right answer only moves a card that was due), and a quiz seen through brings the rest of the lesson in behind them, waiting in box 0, which the review lets in twelve a day (`NEW_PER_DAY`) from the next day on, in lesson order. The bar's Review button appears when cards are due and runs them thirty at a time, the first two boxes to recognise and later ones to say; the cards file is fetched for its count only once something is in review. The page opens on [kannada/today.js](kannada/today.js)'s today view, unless the whole note was last open: the day's plan (the note's Daily Routine as a checklist: Review, Read it out loud, Quiz, Listen, Say it to someone, the last showing the lesson's Say it today lines), then only the lesson you are on; every other part and lesson is `display: none` (screens only; print gets the whole note), and the bar's strip keeps just Today, Start here and Whole note, which lead it. Each lesson ends on a Done button beside its quiz (render.js writes both); Done brings the lesson's cards into the review and moves you on, and the next lesson waits for tomorrow (a "done for today" panel) unless you choose to go ahead. In the today view a lesson's hash (`#lesson-12`, or a heading inside it) shows that lesson alone with a way back, and any other heading opens the whole note there without making it the view next time. The Lessons sheet fills in done lessons and dashes the one you are on. So the note never flashes up first, a small inline script in the head (CSP-hashed at build) adds `is-today` to the root before first paint, and the note stays invisible until today.js adds `is-ready` (or for three seconds, should the script fail). A first visit opens on Start here above the plan (static in index.html: the three spelling rules, with the note's own examples, and how a day goes), until its Start button, a lesson done or a card in review; the bar's Start here link brings it back. store.js also keeps the lesson you are on, the lessons done and when, today's ticks, the day's streak, whether you have started and the last view. Wider screens put each lesson's number in a 120px gutter, and a print stylesheet prints it black on white. Each lesson is `content-visibility: auto`, so a phone lays out only the lessons near the screen (first paint, Cover and a rotation stay quick). Reading where anything inside a skipped lesson sits lays it out again, so main.js finds the lesson on screen by the lesson sections themselves, never their headings. Skipping clips a lesson to its box, so the box reaches over the page's side padding, where the tables bleed, and on phones a lesson's last margin is dropped to keep the gap it used to fold into. It is `noindex` and left out of the sitemap.
- **Exercises page**: [exercises/](exercises/) is served at `/exercises`, which nothing links to since /start's Fit group (and its Exercises link) went; it is reached by its URL. It lists five exercises, Squats, Glute Bridges, Plank, Pushups and Band Rows, numbered in the order the user gave them, each a link to its YouTube video that opens in the same tab, as /start's links do, so Back returns to the list. Just `index.html` and `style.css`, no script, on /start's pure black with its tokens and the shared `public/fonts/`; a "‹ Start" link leads back, in the 120px gutter on wider screens. It is `noindex` and left out of the sitemap.
- **Multi-page Vite build** with `v1/index.html`, `v2/index.html`, `v3/index.html`, `v4/index.html`, `start/index.html`, `kannada/index.html`, and `exercises/index.html` as inputs, output to `dist/`; that directory is what gets uploaded as the Pages artifact. The `root-default` plugin in [vite.config.js](vite.config.js) copies each default page into place (`DEFAULT_PAGES`): built `v1/index.html` → `dist/index.html`, so `/` serves v1. Assets are hashed; each page's CSS bundle is inlined into its HTML by the `inline-css` plugin, so production has no render-blocking stylesheet request.
- **`public/`** is copied verbatim into the build: `CNAME`, favicons, manifest, `robots.txt`, the redirect stubs (`cv.html`, `resume.html`), the `/start` service worker (`start-sw.js`), v1's `fonts/`, and `assets/` (images + `resume.pdf`). The favicons (`favicon.svg` with its PNG/ICO renders, plus the full-bleed `icon-maskable.svg` that `apple-touch-icon.png` is rendered from) are shared by every page and linked with a `?v=` query: bump it on every page, `404.html` included, when the icons change, or browsers keep showing the cached ones.
- **CSP**: inline theme bootstraps, JSON-LD scripts, and the inlined stylesheets are tightened at build time by the `csp-inline-hashes` Vite plugin in [vite.config.js](vite.config.js), which computes SHA-256 hashes for each inline `<script>`/`<style>` and replaces `'unsafe-inline'` in the CSP meta tag. Dev mode keeps `'unsafe-inline'` so HMR works.
- **Build-time values**, all in [vite.config.js](vite.config.js): the `build-stamps` plugin fills tokens in every page, in dev as well as the build — `__BUILD_DATE__`, `__BUILD_YEAR__`, and the years since the career began in June 2019 (`CAREER_START`) as `__YEARS__` (7), `__YEARS_00__` (07), `__YEARS_WORD__` (seven), `__YEARS_WORD_CAP__` (Seven) and `__YEARS_ORDINAL_CAP__` (Seventh). Write those tokens, never the number, wherever copy states the years. The one exception is `og-cover.jpg`/`.webp` (v1–v3's card), which has "7 years" drawn into it. The sitemap lists only `/`, with the build date as `lastmod`, and `/.well-known/security.txt` is emitted with an `Expires` 364 days out (RFC 9116 wants less than a year); its contact address is `SECURITY_CONTACT`.
- **404 page**: [public/404.html](public/404.html) is a self-contained static page that GitHub Pages serves for unknown routes.

## Site Structure

```
/                 → portfolio, v1 design (default; build-time copy of /v1/)
/v1               → portfolio, v1 design
/v2               → portfolio, v2 design
/v3               → portfolio, v3 design
/v4               → portfolio, v4 design
/start            → start page, the browser homepage (noindex)
/kannada          → Kannada Gottilla, the Kannada lessons note as a page (noindex)
/kannada/anki.txt → its cards as an Anki deck, written at build time
/exercises        → exercise videos, reached by URL only (noindex)
/cv, /resume      → meta-refresh redirect to /assets/resume.pdf
                    (static stubs in public/; dev server rewrites
                     /cv → /cv.html via html-routes plugin in vite.config.js)
/sitemap.xml      → generated at build time
/.well-known/security.txt → generated at build time
```

The dev server mirrors production routing: the `html-routes` plugin rewrites `/` and `/v1` → `/v1/index.html`, `/v2` → `/v2/index.html`, `/v3` → `/v3/index.html`, `/v4` → `/v4/index.html`, `/start` → `/start/index.html`, `/kannada` → `/kannada/index.html`, and `/exercises` → `/exercises/index.html`.
