# /start — Keypad

The browser homepage: every bookmark a key, each group a block of keys under its name, the blocks closing into one rectangle sized to the window. [index.html](index.html) holds the bookmarks, [style.css](style.css) the layout, [prompt.js](prompt.js) the prompt, and [main.js](main.js) imports the prompt and settings and registers the service worker.

Keypad is the only design, and there are no `/start/vN` pages. The two it replaced in November 2026 (lists in columns, and *Shelves*) are in the git history, with the `start/bookmarks.html` the three shared.

**Settings**: the gear beside Pomodoro opens an appearance sheet with the [shared dark palettes](../shared/themes.js), preset and custom accents, and a plain or tinted background. Black with a plain background uses the keypad's default surfaces. [theme.js](theme.js) derives the key faces and keeps shortcut legends, quiet text and accents readable. [settings.js](settings.js) builds the controls the first time the sheet opens, applies changes immediately, saves them under `start-settings`, and syncs them across tabs. The head's inline script applies the saved `paint` tokens before first paint.

**Bookmarks**: the groups, the links and their order are in [index.html](index.html); don't copy them into this file. A bookmark is a plain `<li>` link whose icon is a `<symbol>` in the page's sprite (`si-*` Simple Icons, `logo-*` single-colour site logos, `mdi-*` Material Design Icons; 24×24, `currentColor`). Optional attributes:

- `data-alias`: space-separated short codes the prompt matches first.
- `data-search`: a search URL with `%s`; an alias plus a query (`y lofi`) opens it.
- `data-also`: more URLs, space-separated, opened in new tabs along with the href. Write `data-tabs` beside it, their count plus one for the href, which the key prints; nothing counts it for you.
- `data-opens` is generated by `opener-sites` in vite.config.js in dev and production. On the Invest key it lists the hosts read from /invest's `ol.sites`, so the prompt can find Invest by a host such as "kite".

**This site's pages** are keys too: Code (/code) in Code, System Design in Design, Language (/kannada) in Learn, and Invest and Downloads, the last two keys in Misc. **Pomodoro** is the timer icon beside Settings at the end of the prompt's row, and its entry in the hidden list gives the prompt its name and alias `p`. Fit and Varsity have no keys since November 2026 (the user opens Fit from Obsidian). Invest and Downloads open [/invest](../invest/CLAUDE.md) and [/downloads](../downloads/CLAUDE.md), each of which opens several sites from a list of its own. /downloads keeps its sites in the browser, so the prompt knows only its name. The Cashflow sheet and the IPO trackers have had no keys of their own since November 2026: Invest opens them, and the prompt finds it by them ("docs", "ipo").

**Hello Interview** opens the user's offline copy of the site, never hellointerview.com (their choice, November 2026): `http://localhost:8765/`, served on their Windows PC by `C:\Users\sourav\Downloads\Learn\HelloInterview\_offline\serve.py`, which a shortcut in the Startup folder starts at login. A `file://` link can't be used: browsers refuse to open one from a web page. On other devices the key doesn't open.

**Groups**: the most used links are the first group, Daily, pinned to the top. The groups are Daily, Code, Design, Learn and Misc, in that order. Each `section.group` has a class naming it. Code and Design each have two columns. The other groups use `--daily`, `--learn` and `--misc` to set their widths for each layout.

**Hooks**: style.css and prompt.js rely on the markup's hooks: `.prompt` with `#q` and `#hint`, and each group a `section.group` holding an `h2` and a `ul.links` of `<a>`s with an `.icon` and a `.name`. The hidden `ul.links` after the groups holds pages with no key; its links need only a `.name`. Each group's section also carries its `group-*` class (see Groups). The `h1` (the page's title, Hope) is for screen readers only. Keep those when changing the markup.

- **Legends**: a key prints its short code (`data-alias`) top left and, when it opens several tabs, their count top right, from `data-tabs`. Both are CSS `content` with empty alt text, so screen readers read only the name.
- **Layout**: one grid of key columns (`--cols`). A group spans as many columns as it has keys per row. The arrangement follows the window's shape:

  | Window | Columns | Rows of groups |
  |---|---|---|
  | under 360px | 2 | each group a row of its own, two keys wide |
  | phones, and from 760px windows narrower than 1:1 | 4 | Daily (one row of four) / Code (two by two) Design (two by two) / Learn (a row of two) Misc (two by two) |
  | from 760px and 1:1 or wider | 6 | Daily (two by two) Code (two by two) Design (two by two) / Learn (a row of two) Misc (a row of four) |
  | from 930px: under 455px tall, or 3:1 or wider and under 770px tall | 9 | all five in one row, with Learn one by two and the others two by two |

  **The arrangements count on each group having four links, except Learn, which has two.** Check every layout after changing the groups. 1:1 is where six columns start to give larger keys (four used to lose at 4:5, before the November 2026 regrouping). **Nine columns are kept for short windows**, the user's choice in November 2026 (they were twelve then): stretched across a 21:9 screen they made one band from edge to edge with most of the height empty. They take over only where six columns would scroll (under 455px tall) or where their keys come out at least a fifth larger in area (3:1 and under 770px tall); the comment above the rule in style.css works it through.

  In four columns, a spacer between the second and third Daily keys aligns its pairs with Code and Design. In six columns, Learn sits under Daily and Misc spans the width of Code and Design. In nine columns, Learn's keys are a column wide, the narrowest on the page.
- **Fit**: from 760px the page is sized to the window and centred. `--key`, a key's height, is the largest at which the arrangement fits both ways, up to 160px, and the gaps, icons and type all follow it. The formula's numbers come from the gap ratios, the tallest the prompt and a heading get (47px and 24px), and `--across`, how many keys wide the page is while its narrowest keys are square, gaps and padding included (0.35 + 1.175 × `--cols`, so style.css computes it: 5.05 and 7.4; in nine columns, where Learn's one-column keys are the narrowest, 0.35 + 1.25 × `--cols`, 11.6), as the comment above it in style.css spells out: change one and the other has to follow, or the page stops fitting. A key is between square and a quarter wider than tall. On a maximised window the page fills the window's height and half to two thirds of its area: 2560 × 945px gives six columns of keys at the 160px cap (200 to 206px wide), 1536 × 725px six of 140px (175 to 180px wide).
- **Smallest**: a key goes down to 80px, the least that holds a name on two lines (the second runs into the key's lower padding); names wrap in keys under about 97px wide. Nine columns start at 930px, where their keys are 80px wide, and six reach 80px only in windows under 455px tall; half a laptop's screen (768 × 725px) gets six columns of 104px keys. In four columns from 760px, only in tall windows where keys are wide, it goes to 72px. "Downloads" needs a key about 67px wide with the key's 2px side padding; from 760px every key is wider.

**Prompt**: the header comment in [prompt.js](prompt.js) describes how the prompt matches and ranks. Links open in the same tab because the page is the browser homepage. Set as a browser search engine, `https://souravas.com/start/?q=%s` takes the prompt's queries from the address bar: the page replaces itself with what Enter would open, or, when that opens several tabs (which needs a click or key press), leaves the query in the prompt. **An address in `?q=` also waits for Enter, never opening by itself**: otherwise anyone could write a souravas.com link that lands on a page of theirs. Only the page's own bookmarks, their searches and Google open unasked. Clicking a group heading (a button injected by `prompt.js`) opens the whole group in new tabs; browsers block every tab after the first until the site is allowed pop-ups.

**Offline**: [public/sw.js](../public/sw.js), the service worker the personal pages share, is registered in production by main.js with the scope `/start`. For this page it serves the page from cache and refreshes the cache in the background, so a deploy shows up on the second open. When the server returns `304` for the HTML, the worker keeps the whole cached copy and skips checking its fonts. A browser that opened one of the old designs at /start/v1, /start/v2 or /start/v3 (now 404s) keeps that design's worker and cache, and goes on serving it at that address until the worker is unregistered (`chrome://serviceworker-internals` or the browser's site settings); /start itself is unaffected.
