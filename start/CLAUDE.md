# /start

The browser homepage, in three designs, each a folder with its own notes: [v1/](v1/CLAUDE.md) (`/start/v1/`, the first design, plain lists in columns), [v2/](v2/CLAUDE.md) (`/start/v2/`, *Keypad*) and [v3/](v3/CLAUDE.md) (`/start/v3/`, *Shelves*). v2 and v3 were added in November 2026 for the user to try as the homepage; the user then made Keypad the default and moved the first design to /start/v1. Shelves is still a trial.

**The default**: /start shows Keypad at its own address, as / shows the portfolio's v1, rather than redirecting, so the address bar and `?q=` keep `/start/`. The `root-default` plugin copies the built `start/v2/index.html` to `start/index.html` (`DEFAULT_PAGES` in vite.config.js), and the `html-routes` plugin's dev rewrite serves `start/v2/index.html` at `/start`. To make another design the default, change both. There is no `start/index.html` in the source.

**Bookmarks**: [bookmarks.html](bookmarks.html) owns the groups, the links and their order; don't copy them into this file. The `start-bookmarks` plugin puts it, the icon sprite and `<main>`, in place of each design's `<!--bookmarks-->` marker (in dev too), so a bookmark is only ever added, moved or removed there, and shows on all three. A bookmark is a plain `<li>` link whose icon is a `<symbol>` in the sprite (`si-*` Simple Icons, `logo-*` single-colour site logos, `mdi-*` Material Design Icons; 24×24, `currentColor`). Optional attributes:

- `data-alias`: space-separated short codes the prompt matches first.
- `data-search`: a search URL with `%s`; an alias plus a query (`lc two sum`) opens it.
- `data-also`: more URLs, space-separated, opened in new tabs along with the href. The plugin adds their count, plus one for the href, as `data-tabs`, which v2 and v3 print on the link.

There is no pinned row: the most used links are the first group, Daily. Every group holds six links or four, the groups of six first, so wherever a design sets a group's links two to a row (all three on phones, Keypad everywhere) no row is left half full, and v3's shelves stay within its six columns. Keep that in mind when adding a link: a fifth or seventh leaves a gap, and a seventh breaks v3's row (see each design's notes).

**Hooks**: every design's stylesheet, and prompt.js, rely on the markup's hooks: `.prompt` with `#q` and `#hint`, and each group a `section.group` holding an `h2` and a `ul.links` of `<a>`s with an `.icon` and a `.name`. Keep those when changing the markup. `column-start` concerns only v1, and each design's notes say what a new link or group can break in its layout.

**Prompt**: the header comment in [prompt.js](prompt.js) describes how the prompt matches and ranks; each design's `main.js` only imports it and registers the service worker. Links open in the same tab because the page is the browser homepage. Set as a browser search engine, `https://souravas.com/start/?q=%s` takes the prompt's queries from the address bar: the page replaces itself with what Enter would open, or, when that opens several tabs (which needs a click or key press), leaves the query in the prompt. **An address in `?q=` also waits for Enter, never opening by itself**: otherwise anyone could write a souravas.com link that lands on a page of theirs. Only the page's own bookmarks, their searches and Google open unasked. Clicking a group heading (a button injected by `prompt.js`) opens the whole group in new tabs; browsers block every tab after the first until the site is allowed pop-ups.

**Offline**: [public/sw.js](../public/sw.js), the service worker the personal pages share, is registered in production by each design's `main.js` with the scope of the address the page was opened at: `/start/v1`, `/start/v2` or `/start/v3`, and `/start` for the default's copy, so each has its own worker and cache. For these pages it serves the page from cache and refreshes the cache in the background, so a deploy shows up on the second open. A browser that had the first design as /start shows it once more after the switch to Keypad, then Keypad. (The worker was `start-sw.js` until November 2026; a browser still holding that one moves over on its second open.)

**Dropping a design**: delete its folder and its entries in vite.config.js (`rolldownOptions.input`, both rewrites in `html-routes`, the page counts in the comments), its row in the root CLAUDE.md's Pages table and its mentions here and in prompt.js and sw.js. Drop the default only after another design takes its place (see *The default*). If only one design is left, the `start-bookmarks` plugin can go, with bookmarks.html folded back into its page. A browser that opened a dropped design keeps its worker and cache: it goes on serving the design from cache until that worker is unregistered (`chrome://serviceworker-internals` or the browser's site settings).
