# /start/v2 — Keypad

/start's default design since November 2026 (see [../CLAUDE.md](../CLAUDE.md), *The default*): every bookmark a key, each group a keypad two keys wide. The build copies this page to /start, so a change here shows at both addresses. [index.html](index.html) is only a head and a `<!--bookmarks-->` marker, which the `start-bookmarks` plugin fills with [../bookmarks.html](../bookmarks.html), so **bookmarks are changed there, never here**. [main.js](main.js) imports /start's prompt (`../prompt.js`) and registers `/sw.js` with the scope of the address it was opened at (`/start/v2`, or `/start` for the copy), which serves the page from cache at once. Only [style.css](style.css) is this page's own.

- **Legends**: a key prints its short code (`data-alias`) top left and, when it opens several tabs, their count top right, from `data-tabs`, which the plugin adds (the URLs in `data-also` plus the href). Both are CSS `content` with empty alt text, so screen readers read only the name.
- **Layout**: one grid. Phones put the keypads two to a row, from 760px four to a row (the four groups of six, then the three of four), and from 1280px all seven go in one row. At 1280px a key is 77px wide, just room for "AlgoMonster" on one line in the 12px names use below 1440px; a wider gap, more padding or a longer one-word name there would break a word in two. A name on two lines runs into the key's lower padding, which is sized for it at the smallest key (80px).
- **Height**: from 760px, `--key` and `--gap` grow with the window's height (80→96px and 16→28px over 560–800px of it). The tallest keypads set the page's height: six links, three rows of keys. The one-row page fits a window about 370px tall, the four-to-a-row page (760–1279px wide) one about 580px tall.
